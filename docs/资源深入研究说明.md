# CakeHome 资源深入研究说明

> 2026-09-12 · 基于**运行时实测**（Unity 在跑，bridge 查询）+ 代码机制 + meta 结构
> 方法：不靠文件名猜，从「它出现在哪个场景对象下」+「哪个脚本在用它」反推用途

## 一、三消棋盘：Back + Icon 两层结构

**运行时实测**（枚举 `TileBehavior` 的子 SpriteRenderer）：

```
Tile C1T4  (TileBehavior)
├── Back = tile_background      ← 棋盘格底座，54 格共用
└── Icon = tile_c1_t4           ← 该格的棋子图案
```

同时刻棋盘上实测分布：
```
tile_background × 54
tile_c1_t1 ×3   tile_c1_t2 ×6   tile_c1_t3 ×3   tile_c1_t4 ×6
tile_c2_t1 ×3   tile_c2_t2 ×3   tile_c2_t3 ×6   tile_c2_t4 ×6   tile_c2_t5 ×3
tile_c3_t1 ×6   tile_c3_t3 ×3   tile_c3_t5 ×6
```

### 命名与机制
`tile_c{集合}_t{等级}`

| 维度 | 含义 | 代码依据 |
|---|---|---|
| `c` | 主题集合（甜点/咖啡/糖果） | `TileData.collectionID` |
| `t` | 等级 1~5 | `TileData` 索引 |
| 解锁 | 按关卡逐级放出 | `LevelDatabase.AvailableForLevel()` → `AvailableFromLevel <= levelId` |
| 每关种类 | 随机取 N 种 | `LevelData.ElementsPerLevel` |

### 结论
- **Icon 是玩法信息载体** —— 玩家靠图案判断能否消除、是几级
- **Back 是共用底** —— 必须中心留白（上面叠 Icon）
- 🔴 **两者都不能改变图案**；Back 可换色但须留白

## 二、障碍瓦片（Special 6 张）

| 资源 | 脚本 | 机制 | 约束 |
|---|---|---|---|

🔴 形状与阶段序不可改。

## 三、Merge 合成链物品（原以为的"三消棋子"，实为门店合成物）

**运行时实测位置**：
```
Game Area/Items/Merge Item(Clone)/Graphics/Locked Mask/Item/   ← 合成台物品
Flying Objects/MergeFlyingIcon/Icon/                           ← 合成飞行动画
Game Area/Items/Locked Item(Clone)/Graphics/Item/             ← 上锁物品
```

**配置来源**：`MergeDatabase.asset` → `items[].grades[].sprite`（每级一个 Sprite）

**代码结构**：
```csharp
MergeItemData { typeId, itemType, prefab, MergeGradeData[] grades }
MergeGradeData { Sprite sprite, displayName, description, config, customShadow... }
```

### 命名与机制
`game_{族}_{级}.png`，如 `game_cake_1` ~ `game_cake_12`

| 族 | 级数 | 链条（从原图采样确认） |
|---|---|---|
| cake | 12 | 面粉袋→面糊→酥饼→曲奇→杯子蛋糕→玛芬→草莓挞→樱桃芝士→提拉米苏→层蛋糕→芝士块→甜品杯 |
| coffe | 12 | 咖啡豆→咖啡粉→纸杯→橙套杯→橙陶杯→白瓷杯→拿铁→卡布→猫脸拉花→冰咖→阿芙佳朵→冰杯 |
| kettle | 9 | 陶壶→红釉壶→红细颈→银鸣笛→银手冲→玻璃滤壶→电水壶→半自动咖啡机→意式机 |
| mixer | 9 | 量勺→蛋抽→空碗→碗+蛋抽→手持棒→手持机→带碗手持→厨师机→厨师机+打蛋头 |
| candy | 5 | 紫圆糖→蓝包装糖→棒棒糖→糖果罐→礼品盒 |
| soda | 5 | 冰块→空瓶→可乐瓶→开盖→倒出 |
| placeholder | 7 | 简店→…→完整烘焙店面 |
| coin / energy / gem | 1~2 | 金币 / 闪电 / 宝石 |

### 结论
- **等级递进 = 玩法核心**（合成链必须看得出升级）
- 🔴 同一族的 N 级**不能画成相似物**，否则玩家看不出合成进展
- ✅ 可用 AI 重绘，但**必须逐级描述具体物品**（已实现于 `Tools/gen_all.py` 的 `PIECE_CHAINS`）

## 四、UI 九宫格（19 + 8 张）

**运行时实测**：`Image.Type` 统计 → **Sliced = 195 个**、Simple = 652、Filled = 5

### 结构
`.meta` 的 `spriteBorder` 把图切九块，四角不拉伸 / 四边单轴 / 中心双轴。

| 资源 | 尺寸 | spriteBorder | 边框占比 |
|---|---|---|---|
| `btn_gray/green/orange/purple` | 156×216 | (58,76,50,58) | **37% / 27%** |
| `ui_button_*` ×5 | 1024² | (452,353,452,353) | **44% / 34%** |
| `panel_*` ×3 | 512² | (100,120,100,100) | 20% |
| `ui_panel_white` 等 | 512² | (80,80,80,80) | 16% |

**边框占比 37~44%** → 可拉伸区极小，边缘像素一变就撕裂。

### 结论
🔴 **不可重绘**。实测 3 轮：模型把 "uniform center" 理解成「画黑洞」或产出直角矩形。
✅ **唯一安全做法**：保留原几何，只调色调（`Tools/reskin_9slice.py` 已实现）。

## 五、TMP 字体字符图集（6 张）

`Fonts/FredokaOne 50`（Texture/Glow/Outline/Outline Light）、`FredokaOne 120`（2 张）

- 是 **TextMeshPro 字符位图图集**，每小格是一个字符的一层
- Unity 按字符坐标采样，**图里是什么就显示什么**

🔴 **不可重绘**（实测被画成「裱花相框」，字全没了）。
**另注**：项目已知问题 —— `FredokaOne 50` 无 CJK 字形无 fallback，中文显示为空格。

## 六、大地图（7 张）

**运行时实测**：`map_level × 40`（关卡按钮）、`map_c0/c1/c2 × 1`、`cloud × 4`

| 地块 | 主色 | 季节 |
|---|---|---|
| `map_c1` | 黄绿+亮绿 | 春·草地 |

## 七、门店场景 Zone1（22 张）

`z1_{house,table,bush,fence,fountain}_{1..4}`

**运行时实测**：`z1_house_4 / z1_fountain_4 / z1_bush_4 / z1_fence_4 / z1_table_4` 各 1 个，挂在 `UI Merge Menu (Active)/Zone Container/Zone 1(Clone)` 下。

### 机制
- 受 **buildingId 槽位**约束，与**玩家存档绑定**
- 每物件 4 档升级，成本固定（Zone1 565 / Zone2 3955 / Zone3 9605）
- `Zone 1.prefab` 直接 GUID 引用这 20 张

### 5 槽位映射（已有设计）
| 槽位 | 原物件 | 目标 |
|---|---|---|
| building_1 | house | 后墙左高柜 |
| building_2 | fountain | 前景玻璃柜 |
| building_3 | table | 圆桌餐椅 |
| building_4 | fence | 右高柜 |
| building_5 | bush | 三层点心塔 |

🔴 换内容须**整套换**（背景+5物×4档），且 `buildingId`/存档/成本逻辑不变。
